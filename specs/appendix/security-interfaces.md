# 外部安全接口声明

本文档定义了 ACT 协议规范中引用的外部安全服务接口。这些接口的具体实现可由实现方依据自身安全架构选择适用的安全组件（如 ASL 协议组件、HSM、TEE 内嵌安全服务等），但应满足本文件声明的接口契约。

## 1 私钥安全存储与访问控制接口

### 接口标识

`SecurityProvider.keyStore`

### 接口契约

| 操作 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `generateKeyPair` | 算法标识、密钥用途、访问策略 | 密钥标识、公钥材料 | 在安全执行环境中生成密钥对，私钥不可导出 |
| `sign` | 密钥标识、待签名载荷（已规范化字节序列）、载荷类型 | 签名值、算法标识 | 使用指定密钥对载荷进行签名 |
| `verify` | 公钥材料、待验证载荷、签名值 | 验证结果 | 验证签名有效性 |
| `getPublicKey` | 密钥标识 | 公钥材料 | 获取指定密钥的公钥 |

### 安全要求

- 私钥应以不可导出方式存储于安全执行环境中；
- 密钥调用应受访问控制策略约束；
- 签名操作的输入应为已完成规范化处理的字节序列。

## 2 用户核身机制接口

### 接口标识

`SecurityProvider.userAuthentication`

### 接口契约

| 操作 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `authenticateUser` | 用户身份标识、核身方式偏好列表 | 核身结果（成功/失败）、核身方式、核身时间戳 | 唤起用户核身流程并返回结果 |

### 安全要求

- 核身方式应包括但不限于：生物识别（`FACE_RECOGNITION` / `FINGERPRINT`）、支付密码（`PASSWORD`）、动态验证码（`OTP`）；
- 核身结果应包含核身方式与核身时间戳，作为后续签名操作的授权依据。

## 3 签名服务接口

### 接口标识

`SecurityProvider.signingService`

### 接口契约

| 操作 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `signPayload` | 待签名的 ISR 载荷（JCS 规范化后的字节序列）、签名方身份标识 | 签名值（Base64url 编码）、签名算法标识、核身完成时间戳 | 对载荷执行签名并返回结果 |

### 安全要求

- 签名前应完成用户核身；
- 签名算法应支持 `ES256` 和 `SM2-SM3`；
- 签名输入应为 RFC 8785 JCS 规范化后的字节序列。

## 4 安全时间源接口

### 接口标识

`SecurityProvider.secureTime`

### 接口契约

| 操作 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `getSecureTime` | 无 | 受保护时间戳（ISO 8601 UTC） | 获取防篡改的当前时间 |

### 安全要求

- 时间源应具备防篡改能力；
- 时间精度应满足协议有效期校验要求。

## 5 密码学哈希与规范化接口

### 接口标识

`SecurityProvider.crypto`

### 接口契约

| 操作 | 输入 | 输出 | 说明 |
|------|------|------|------|
| `hash` | 算法标识、输入字节串 | 摘要值 | 计算密码学安全摘要 |
| `canonicalizeJson` | JSON 对象 | 规范化字节序列 | 按 RFC 8785 JCS 规范执行 JSON 规范化 |

### 安全要求

- 哈希算法应至少支持 SHA-256；
- JSON 规范化应严格遵循 RFC 8785 JCS 规范。
