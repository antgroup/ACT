# 场景一：信任服务提供商视角 - 即时支付

## 场景描述

作为信任服务提供商（TSD），我为 ACT 协议生态提供底层信任基础设施，包括智能体身份管理、可信存证、存证验证与争议解决服务。在即时支付场景下，我为交易各方提供身份认证和存证服务。

## 角色定位

- **我是**：信任服务提供商（Trust Services Provider, TSD）
- **服务对象**：ACT 协议生态中的全部参与方（买方智能体、卖方智能体、商户、PSP）
- **核心能力**：智能体身份管理、可信存证、链上锚定、存证验证、争议处理
- **功能定位**：为其他协议域（ADD、CID、PSD）提供信任基础设施

## 我的核心职责

### 1. 智能体身份管理（`TSD-IDM-AID`）

#### 1.1 did:act 身份注册
- 为 ACT 协议生态中的智能体分配 `did:act` 去中心化身份标识
- 维护 DID Document，包含：
  - 智能体的公钥（用于签名验证）
  - 服务发现端点（A2A 接口地址）
  - 能力声明引用
  - 状态信息（激活/吊销）

#### 1.2 身份信息核验
- 核验参加交易的各方智能体的 `did:act` 身份有效性
- 验证公钥与身份标识的绑定关系
- 检查身份状态（是否被吊销、过期）

#### 1.3 DID 解析服务
- 提供 `did:act` 身份的解析服务
- 接受 DID 标识符，返回对应的 DID Document
- 支持身份从 `did:act` 到其他 DID 方法的跨链解析

### 2. 存证事件记录（`TSD-ATT-OFF`）

在即时支付场景下，记录以下关键存证事件：

#### 2.1 委托授权域存证事件
- **IAC 签发事件**：记录 IAC 的签发时间、签发人、约束内容哈希
- **IAC 状态变更事件**：记录 IAC 的撤销、过期、更新等状态变化

#### 2.2 商业交互域存证事件
- **购物车确认事件**：记录交易双方确认的商品清单、金额、时间戳
- **支付能力协商事件**：记录买卖双方达成的支付方式约定

#### 2.3 支付服务域存证事件（即时支付核心）
- **支付请求事件**：
  - 支付方身份
  - 交易订单信息哈希
  - 支付金额、收款方
  - 请求时间戳

- **支付结果事件**：
  - 支付成功/失败状态
  - 交易流水号
  - 完成时间戳
  - 参与方签名

### 4. 链上存证锚（`TSD-ATT-OCA`）

- 定期将一批存证记录的聚合摘要写入 ACT Trust Chain
- 生成链上存证锚（Attestation Anchor）
- 锚点包含：
  - 这批存证记录的 Merkle Root
  - 写入区块高度和时间戳
  - 存证服务方签名

### 5. 存证验证服务（`TSD-ATT-SVF`）

#### 5.1 存证记录查询
- 提供存证记录的查询接口
- 支持按参与方、时间范围、事件类型、交易号等维度查询

#### 5.2 存证记录验证
- 验证存证记录的真实性和完整性
- 验证记录签名（事件源签名 + TSD 签名）
- 验证链上锚定（比对记录的 Merkle Proof 与链上锚点）

#### 5.3 状态证明服务
- 为参与方提供某事件已被存证的证明
- 可用于向第三方证明交易发生过

### 6. 即时支付场景下的具体职责

```
交易流程                        TSD 介入点
─────────────────────────────────────────────────────────────
买方智能体发起支付请求    ──►   记录"支付请求"存证事件

PSP 唤起收银台                  （用户确认无TSD介入）

用户实时确认                    （用户确认无TSD介入）

PSP 完成扣款              ──►   记录"支付结果"存证事件

PSP 通知商户/买方        ──►   记录"支付通知"存证事件（可选）

商户履约                ──►   记录"履约完成"存证事件（可选）

交易完成              ──►  批量锚定上链（ACT Trust Chain）
```

### 7. 争议处理服务支持（`TSD-ATT-DSP` 前置）

在即时支付场景下，虽无即时争议，但需准备：
- 交易发生时的完整存证档案
- 验证各参与方身份的可追溯记录
- 为后续可能的争议提供证据基础

## 参与方的存证接入

### 买方智能体接入
- 在发起支付请求前上报意图存证事件
- 在获得支付结果后上报完成存证事件

### PSP 接入
- 在关键节点上报存证事件：
  - 支付请求接收
  - 用户确认完成
  - 扣款成功/失败
  - 结算完成

### 商户/卖方智能体接入
- 上报履约相关存证事件
- 在争议时提供证据

## 技术要求

- 提供高可用、低延迟的存证事件接收接口
- 实现存证记录的加密存储与完整性保护
- 提供存证记录的查询和验证 API
- 与 ACT Trust Chain 对接实现链上锚定
- 提供 DID 解析服务支持 `did:act` 方法

## 隐私与合规

- 存证记录采用哈希存储原始内容，不上链敏感明文
- 仅记录必要的交易元数据（金额、参与方 DID、时间戳）
- 支持参与方对存证记录的访问控制设置
- 遵循数据最小化原则，符合隐私法规要求

## 与场景二/三的区别

| 维度 | 即时支付场景 | 委托/A2A 场景 |
|------|-------------|--------------|
| 存证频率 | 单笔交易，存证次数少 | 多笔交易，存证次数多 |
| 身份核验 | 单次交易时的身份核验 | 持续的 IAC 授权状态核验 |
| 争议类型 | 主要是交易执行争议 | 可能有授权范围争议 |
| 信任重点 | 交易发生的不可否认性 | 授权边界的合规性验证 |
| 存证复杂度 | 相对简单的事件链 | 复杂的多方交互事件链 |
