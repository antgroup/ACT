# 场景一：支付服务提供商(PSP)视角 - 用户即时支付

## 场景描述

作为 PSP，我为用户提供支付受理服务，在即时支付场景下负责唤起收银台、核验用户身份、执行扣款并返回支付结果。

## 角色定位

- **我是**：支付服务提供商（Payment Service Provider, PSP）
- **服务对象**：通过平台 Agent 发起支付的用户
- **核心能力**：支付受理、身份核验、资金清算、风控决策

## 我的职责

### 1. 支付标记管理（`PSD-PMT-BND`）
- 为用户生成并管理支付标记（Payment Token）
- 将支付标记与用户的原始支付账户（银行卡、账户余额等）关联
- 确保原始账户信息不暴露给智能体或其他参与方

### 2. 收银台唤起与身份核验
- 接收平台 Agent 通过 `PSD-PAY-INS` 发起的即时支付请求
- 核验支付标记的有效性和绑定关系
- 唤起收银台（App 内网页、短信验证码、生物识别等）
- 核验用户实时在场身份

### 3. 扣款执行
- 用户确认后，执行实际扣款操作
- 从用户原始支付账户划转资金至商户账户
- 支持多种支付方式的内部路由（银行卡、余额、信用支付等）

### 4. 风控决策
- 基于交易特征进行实时风控评估
- 识别异常交易模式（金额异常、频率异常、设备异常等）
- 触发二次验证或拦截可疑交易

### 5. 结果通知
- 向平台 Agent 返回支付结果（成功/失败/处理中）
- 向商户发送支付结果通知
- 提供交易查询和对账接口

### 6. 存证记录生成（可选但推荐）
- 将关键支付事件（支付请求、扣款成功、失败原因等）生成存证事件
- 上报至存证服务提供商，构建可追溯的交易记录

## 关键约束

- **必须**：在即时支付场景下确保用户实时在场确认
- **必须**：支付标记与原始账户的映射关系必须安全存储，不可泄露
- **必须**：遵循多重的风控策略，保护用户资金安全
- **必须**：提供幂等的支付接口，防止重复扣款

## 我的价值

- 作为支付基础设施，为 ACT 协议生态提供安全可靠的支付能力
- 通过支付标记化技术保护用户敏感信息
- 承担资金清算和争议调解的权威角色

## 技术要求

- 实现 `PSD-PAY-INS` 即时支付接口
- 支持支付标记的生成、查询、更新、作废全生命周期管理
- 与银行/卡组织的清算网络对接
- 提供安全合规的密钥管理（HSM 等）

## 安全考量

- 遵循 PCI-DSS 等支付行业安全标准
- 交易数据加密传输与存储
- 严格的访问控制与审计日志
