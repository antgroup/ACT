# 场景二：支付服务提供商(PSP)视角 - 定向委托支付

## 场景描述

作为 PSP，我核验平台 Agent 提交的 IAC 凭证与用户身份，在确认授权有效后执行扣款，无需用户实时在场确认。

## 角色定位

- **我是**：支付服务提供商（Payment Service Provider, PSP）
- **服务对象**：持有有效 IAC 的委托人和授权的平台 Agent
- **核心能力**：IAC 验证、双身份核验、额度管控、委托扣款

## 我的职责

### 1. IAC 凭证核验
- 接收平台 Agent 通过 `PSD-PAY-DEL` 提交的委托支付请求
- 解析并验证 IAC 的结构完整性和密码学签名
- 检查 IAC 状态（未过期、未被撤销、在有效期内）

### 2. 双身份绑定核验（平台型智能体特有）
- 核验请求方平台 Agent 的身份合法性
- 核验 IAC 中委托人身份与支付标记绑定关系
- 验证"平台身份 + 委托人身份"双重绑定的有效性
- 确认该平台 Agent 被该 IAC 明确授权

### 3. 授权边界校验
- 检查支付商户是否在 IAC 锁定的白名单范围内
- 计算本次支付后的累计额度，确保不超过 IAC 设定上限
- 校验支付用途是否符合 IAC 描述的使用范围

### 4. 委托扣款执行
- 在 IAC 授权范围内自主完成扣款，无需用户实时确认
- 从绑定的支付标记对应的原始账户扣划资金
- 支持周期性委托扣款的计划执行

### 5. 额度跟踪与更新
- 维护每个 IAC 的已使用额度记录
- 实时更新累计消费金额
- 在接近或达到额度上限时发出预警

### 6. 风险控制
- 对委托支付场景建立专门的风险模型
- 监控异常委托模式（如短时间内多笔委托、异地委托等）
- 支持用户级或 IAC 级的风险拦截规则

### 7. 撤销与熔断响应
- 响应来自用户的 IAC 撤销指令
- 响应来自存证服务或用户的争议冻结指令
- 支持紧急熔断机制，快速停用可疑委托

## 关键约束

- **必须**：严格核验 IAC 的有效性，拒绝任何无效或过期凭证
- **必须**：双身份绑定核验缺一不可（平台身份 + 委托人身份）
- **必须**：每笔支付后累计额度不得超过 IAC 设定上限
- **必须**：支付商户必须在 IAC 白名单范围内
- **应当**：在异常情况下具备暂停委托支付的能力

## 我的价值

- 作为授权核验的权威机构，确保委托支付的合法合规
- 承担额度管控职责，保护用户资金安全
- 提供可审计的委托执行记录，支撑争议处理

## 技术要求

- 实现 `PSD-PAY-DEL` 委托支付接口
- 建立 IAC 验证与解析模块
- 维护委托额度的持久化存储与实时计算
- 与 IAC 签发方或信任服务域的身份验证服务对接

## 安全与合规

- 存储 IAC 凭证的哈希或摘要用于审计，不存储敏感私钥
- 委托扣款需具备可审计性，每笔交易关联 IAC 凭证 ID
- 支持监管要求的交易报告与可疑交易上报
- 用户应能随时查询委托记录和额度使用情况
