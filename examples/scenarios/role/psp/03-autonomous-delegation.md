# 场景三：支付服务提供商(PSP)视角 - 自主委托 A2A 支付

## 场景描述

作为 PSP，我核验平台 Agent 基于 IAC 和智能体专属子账户发起的 A2A 支付请求，在授权边界内完成多笔智能体间交易的扣款。

## 角色定位

- **我是**：支付服务提供商（Payment Service Provider, PSP）
- **服务对象**：使用专属子账户执行复杂任务的买方智能体
- **核心能力**：A2A 支付核验、子账户管理、预算管控、智能体间清算

## 我的职责

### 1. 智能体专属子账户管理（`PSD-AGT-SUB`）
- 为授权的买方智能体开立专属独立子账户
- 管理子账户与委托人主账户的资金隔离关系
- 为子账户配套生成专属密钥对，支持独立签名授权
- 支持子账户的充值、余额查询、资金调拨

### 2. A2A 支付请求核验
- 接收买方智能体通过 `PSD-PAY-A2A` 提交的 A2A 支付请求
- 解析支付载荷，提取 IAC 凭证、子账户标识、支付金额、卖方信息等
- 核验子账户密钥签名，确认请求来自授权的买方智能体

### 3. IAC 自主委托授权验证
- 验证 IAC 的类型为自主委托（delegation_mode: BOUNDED）
- 核验 IAC 的有效性（签名、过期时间、撤销状态）
- 确认买方智能体在该 IAC 的授权范围内

### 4. 总预算管控
- 维护子账户的预算余额
- 确保所有子任务累计支付不超过 IAC 设定的总预算上限
- 在预算即将耗尽时向买方智能体发出通知

### 5. 多笔交易执行
- 支持买方智能体在任务执行期间发起多笔 A2A 支付
- 每笔支付独立核验，累计受控
- 实时扣减子账户余额

### 6. 跨智能体清算
- 扣减买方智能体子账户资金
- 将资金划转至卖方商户的收款账户
- 支持 T+0 或 T+1 的清算周期

### 7. 支付凭证验证
- 验证 A2A 支付凭证的格式与内容完整性
- 验证凭证中的 IAC 引用与本次交易的 IAC 一致
- 提供凭证验证接口供卖方智能体/商户验证

### 8. 履约后资金释放（可选）
- 支持带担保的 A2A 支付模式，资金先冻结后释放
- 接收履约确认后完成资金最终划转
- 支持争议时的资金冻结与划拨决策

## 关键约束

- **必须**：使用专属独立子账户，与用户主账户完全隔离
- **必须**：所有交易累计支出不得超过 IAC 总预算
- **必须**：核验 IAC 为自主委托类型，且子账户在授权范围内
- **必须**：每笔支付基于有效的子账户密钥签名
- **必须**：子账户资金不足时拒绝支付并返回明确错误

## 我的价值

- 为 A2A 智能体间交易提供可信赖的支付基础设施
- 通过子账户隔离降低用户主账户的风险暴露
- 预算管控防止智能体超支，保护用户资金安全
- 提供跨智能体的统一清算与对账服务

## 技术要求

- 实现 `PSD-PAY-A2A` A2A 支付接口，支持 HTTP 402 语义扩展相关的支付处理
- 实现 `PSD-AGT-SUB` 智能体专属子账户管理接口
- 支持子账户密钥的生成、绑定、轮换、注销全生命周期
- 支持多笔交易的累计额度实时跟踪
- 提供交易流水查询和对账接口

## 安全考量

- 子账户密钥必须安全存储，建议使用 HSM 或安全密钥管理服务
- 子账户与用户主账户的资金流向需可追溯、可审计
- 子账户出现异常时应能紧急冻结并通知用户
- 支持子账户密钥的定期轮换机制

## 与场景二的区别

场景二（定向委托）vs 场景三（自主委托 A2A）：

| 维度 | 定向委托 | 自主委托 A2A |
|------|---------|-------------|
| 资金源 | 用户主账户/支付标记 | 智能体专属子账户 |
| 额度管控 | 按笔/按周期额度 | 总预算上限 |
| 身份核验 | 双身份绑定（平台+用户） | 子账户密钥签名 |
| 交易模式 | 单笔或预设定周期的委托 | 多笔动态 A2A 交易 |
| 收款方 | 固定白名单商户 | 动态发现的卖方智能体 |
| 支付凭证 | 标准委托支付凭证 | A2A 支付凭证 |
