# 场景三：专属型智能体视角 - 自主委托 A2A 支付

## 场景描述

作为专属型智能体，我与用户强绑定，接受用户的自主委托授权，使用专属子账户和预算，在 A2A 生态中自主拆解任务、自主发现卖方智能体、自主完成多笔交易，全程无需用户逐笔介入。

## 角色定位

- **我是**：专属型智能体（Dedicated Agent），具备 A2A 能力和市场发现能力
- **我的用户**：设定任务目标和预算边界的专属委托人
- **核心特征**：自主决策、A2A 互操作、资金隔离、高度信任

## 我的职责

### 1. 任务目标接收与理解
- 通过 `ADD-INT-EAC` 获取用户的复杂任务目标与约束边界
- 利用与用户的长期关系，理解目标的隐含偏好
- 示例任务："帮我安排下周出差，预算 5000 元，偏好南航、四星以上酒店"

### 2. 意图结构化与边界确认
- 生成 `delegation_mode: BOUNDED` 的 ISR
- 明确总预算上限、品类范围、时间约束、品牌偏好等边界
- 与用户确认边界，签发自主委托类型的 IAC

### 3. 专属子账户与预算准备
- 通过 `PSD-AGT-SUB` 管理我的专属子账户
- 与委托人确认预算充值，确保子账户有足够资金
- 子账户配备专属密钥，我的 A2A 支付使用此密钥签名

### 4. 任务自主拆解
基于用户目标，将复杂任务拆解为可独立执行的子任务：
- 出差任务 → 机票预订 + 酒店预订 + 用车服务 + 餐饮预订
- 装修任务 → 设计服务 + 材料采购 + 施工服务 + 监理服务
- 学习任务 → 课程选购 + 教材采购 + 工具订阅

### 5. 服务市场发现
- 基于子任务需求，在 A2A 服务市场发现适合的卖方智能体
- 利用市场提供的评价、历史成交、能力声明进行初步筛选
- 向多个候选卖方智能体发起询价或协商邀请

### 6. 支付能力协商（`CID-PCA-NEG`）
- 与选定的卖方智能体进行支付能力协商
- 匹配双方支持的支付方式、PSP 偏好、结算周期
- 达成一致的支付条件后进入交易环节

### 7. A2A 支付执行
- 接收卖方智能体返回的 HTTP 402 支付诉求
- 构造 A2A 支付载荷，包含：
  - IAC 凭证引用
  - 子账户标识
  - 支付金额、收款方信息
  - 我的专属智能体签名
- 通过 `PSD-PAY-A2A` 提交至 PSP

### 8. 预算与进度管理
- 实时跟踪子任务预算消耗与总预算余额
- 在剩余预算不足时自主调整策略（如选择更经济的选项）
- 向用户汇报进度和预算使用情况

### 9. 履约跟踪与多轮交易
- 携带支付凭证访问卖方智能体提供的资源或服务
- 跟踪履约状态，处理履约异常
- 循环执行步骤4-8直至所有子任务完成

### 10. 结果汇总与学习
- 所有子任务完成后，向用户汇总完整的任务执行报告
- 记录用户反馈，用于后续任务的学习优化
- 支持用户对各子任务的评价和争议提交

## 专属型在 A2A 场景的独特优势

### 1. 深度个性化决策
利用与用户的长期绑定关系，自主决策更贴近用户真实偏好：
- 知道用户偏好靠窗座位、特定品牌
- 了解用户的历史不满意记录，主动规避
- 学习用户的预算分配习惯（如住宿>交通）

### 2. 信任基础支持更高自主权
由于长期一对一关系，用户更可能授予：
- 更高的总预算上限
- 更宽泛的品类范围（"除奢侈品外都可以"）
- 更少的逐笔报告要求

### 3. 身份一致性保障 A2A 体验
专属智能体使用统一身份参与所有 A2A 交互：
- 历史交易记录可累积，形成统一的信任画像
- 各卖方智能体看到的是同一个身份，累积评价
- 避免平台间身份碎片化导致的信用割裂

## 与平台 Agent 在 A2A 场景的差异

| 维度 | 专属型智能体 | 平台型智能体 |
|------|-------------|-------------|
| **决策依据** | 长期用户一对一关系 | 平台级数据 + 通用规则 |
| **资金模式** | 专属子账户，用户事前充值 | 子账户或平台垫资 |
| **身份呈现** | 单一、稳定的专属身份 | 多平台可能的多个身份 |
| **个性化** | 深度个性化（用户专属偏好） | 群体级个性化（用户画像） |
| **A2A 生态** | 作为独立智能体参与 | 作为平台代表参与 |
| **信任积累** | 身份级信任累积 | 平台 + 身份双重信任 |

## 技术要求

- 实现 A2A 协议的智能体能力与发现接口
- 实现 `CID-PCA-NEG` 支付能力协商
- 支持 HTTP 402 语义扩展的支付诉求处理
- 具备任务规划与拆解的推理能力（LLM/RAG 等）
- 与 TSD 信任服务域对接，支持存证上报

## 挑战与应对

### 挑战1：商品发现能力
专属型智能体通常缺乏大平台的商品数据优势。

**应对**：
- 调用平台 Agent 的 `CID-MER-CAT` 接口获取商品数据
- 积极参与 A2A 服务市场，获取卖方智能体的能力声明

### 挑战2：多方协调复杂度
复杂任务涉及多个卖方智能体，协调难度大。

**应对**：
- 使用 A2A 的任务委托与状态同步机制
- 建立任务依赖关系图，合理安排执行顺序

### 挑战3：争议处理责任
多智能体协作场景下，问题归属复杂。

**应对**：
- 全流程存证上报（`TSD-ATT-EVT`）
- 为用户代理争议提交，利用 TSD 争议处理机制

## 参考实现

- 支付宝专属智能助理：用户说"帮我安排全家周末出游，预算 3000"，专属智能体自主完成：
  - 发现景区卖方智能体，购买门票
  - 发现酒店卖方智能体，预订房间
  - 发现餐饮卖方智能体，预订餐厅
  - 全程使用专属子账户 A2A 支付
