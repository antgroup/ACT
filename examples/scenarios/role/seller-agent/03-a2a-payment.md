# 场景三：卖方智能体视角 - A2A 支付

## 场景描述

作为卖方智能体，我在 A2A（Agent-to-Agent）生态中与买方智能体直接协作。通过 HTTP 402 语义扩展发起支付诉求，接收并验证支付凭证，然后提供履约服务。我是 A2A 商业交互中的卖方代理。

## 角色定位

- **我是**：卖方智能体（Seller Agent），A2A 交互中的服务提供方代理
- **我代表**：商户（Merchant），实际提供商品/服务并承担履约责任
- **交互对象**：买方智能体（Buyer Agent），在 A2A 市场中发现我并发起交易
- **核心能力**：A2A 服务发现、支付能力协商、支付诉求生成、凭证验证、资源交付

## 我的核心职责

### 1. 服务市场注册与发现
- **服务注册**：在 A2A 服务市场注册我的服务能力
- **能力声明**：发布支付能力声明（Payment Capability Declaration）
  - 支持的服务类型：机票预订、酒店预订、租车服务等
  - 支持的支付方式、PSP、结算周期
  - 服务边界和约束条件
- **发现端点**：提供服务发现端点供买方智能体查询

### 2. A2A 任务接口实现
- 实现标准的 A2A 智能体任务接口
- 接收买方智能体的任务请求：
  - 机票场景：航班查询、座位选择、出票请求
  - 酒店场景：房态查询、房型选择、预订请求
  - 通用场景：库存查询、价格协商、预订确认

### 3. 支付能力协商（`CID-PCA-NEG`）
在买方智能体发起正式交易前，完成支付能力协商：

**协商请求接收**：
- 接收买方智能体的支付能力查询

**能力声明响应**：
```json
{
  "supported_payment_methods": [
    {
      "network": "cn.alipay",
      "settlement_time": "T+1",
      "currency": ["CNY"],
      "psp_endpoints": ["https://psp.alipay.com/a2a"]
    },
    {
      "network": "act.a2a.token",
      "token_standard": "ACT-PAY-TOKEN-v1"
    }
  ],
  "preferred_method": "cn.alipay",
  "invoice_required": false
}
```

**协商确认**：
- 与买方智能体确认最终采用的支付方式

### 4. 向商户后台查询库存/价格
- 实时查询实际库存和价格
- 获取可预订的资源列表
- 锁定备选库存（协商期间短暂锁定）

### 5. 支付诉求生成（HTTP 402 响应）
在确认交易条件后，向买方智能体返回 HTTP 402 支付诉求：

```http
HTTP/1.1 402 Payment Required
Content-Type: application/json
A2A-Payment-Version: act-a2a-v1

{
  "payment_claim": {
    "claim_id": "claim-2024-001-xyz",
    "created_at": "2024-01-15T09:30:00Z",
    "expires_at": "2024-01-15T09:45:00Z",

    "amount": {
      "value": "299.00",
      "currency": "CNY"
    },

    "payee": {
      "merchant_did": "did:act:merchant-airline-001",
      "merchant_name": "XX航空公司"
    },

    "order": {
      "order_id": "ORD-FLIGHT-20240115-001",
      "description": "北京-上海 经济舱机票",
      "items": [
        {
          "sku": "FLIGHT-CA1234-20240120",
          "name": "CA1234 航班",
          "quantity": 1,
          "unit_price": "299.00"
        }
      ]
    },

    "payment_method": {
      "type": "act_a2a_payment",
      "supported_networks": ["cn.alipay"],
      "psp_endpoint": "https://psp.alipay.com/a2a/pay"
    },

    "fulfillment": {
      "type": "digital_ticket",
      "delivery_endpoint": "https://a2a.merchant-airline.com/deliver/ticket"
    }
  },

  "seller_agent_signature": "<卖方智能体签名>"
}
```

**支付诉求关键字段说明**：
- `claim_id`：支付诉求唯一标识
- `expires_at`：诉求有效期，过期后买方需重新发起交易
- `amount`：支付金额和币种
- `payee`：收款方身份信息（DID）
- `order`：订单详情，用于买方核对
- `payment_method`：期望的支付方式和 PSP 端点
- `fulfillment`：履约方式和交付端点
- `seller_agent_signature`：卖方智能体签名保证诉求真实性

### 6. 支付凭证接收与验证
接收买方智能体返回的支付凭证：

```json
{
  "payment_proof": {
    "claim_id": "claim-2024-001-xyz",
    "transaction_id": "txn-psp-20240115-abc123",
    "paid_at": "2024-01-15T09:35:22Z",
    "amount": {
      "value": "299.00",
      "currency": "CNY"
    },
    "payer": {
      "buyer_agent_did": "did:act:buyer-agent-007"
    }
  },
  "buyer_agent_signature": "<买方智能体签名>",
  "psp_receipt": "<PSP 出具的支付收据>"
}
```

**验证步骤**：
1. 验证 `claim_id` 与我发出的支付诉求匹配
2. 验证金额与诉求一致
3. 验证买方智能体签名
4. 向 PSP 验证 `psp_receipt` 的真实性

### 7. 履约与资源交付
支付验证通过后：
- **出票/预订**：向商户后台系统发起实际出票或预订
- **生成交付凭证**：
  - 机票：生成电子客票、登机牌信息
  - 酒店：生成预订确认号、入住凭证
  - 虚拟商品：生成兑换码、激活码
- **资源交付**：通过 A2A 接口或指定端点向买方智能体交付资源凭证

### 8. 履约回执返回
向买方智能体返回包含支付凭证引用的履约回执：

```json
{
  "fulfillment_receipt": {
    "order_id": "ORD-FLIGHT-20240115-001",
    "status": "fulfilled",
    "fulfilled_at": "2024-01-15T09:36:05Z",
    "payment_claim_id": "claim-2024-001-xyz",

    "deliverables": [
      {
        "type": "flight_ticket",
        "ticket_number": "999-1234567890",
        "flight_info": "CA1234 2024-01-20",
        "passenger": "张三",
        "access_url": "https://api.airline.com/tickets/999-1234567890"
      }
    ],

    "attestation": {
      "event_id": "evt-fulfill-20240115-001",
      "timestamp": "2024-01-15T09:36:05Z",
      "seller_agent_signature": "<签名>"
    }
  }
}
```

**回执应包含**：
- 原始支付诉求引用（建立支付-履约关联）
- 交付物的访问凭证
- 存证事件 ID（用于争议时举证）
- 卖方智能体签名

### 9. 存证事件上报
- 生成履约存证事件（`TSD-ATT-EVT`）
- 上报至存证服务提供商
- 保留完整的交易记录用于争议处理

### 10. 争议配合
- 配合存证服务提供商的争议调查
- 提供交易记录、支付凭证、履约凭证等证据
- 接受并执行争议裁决结果

## 与买方智能体的信用评估

作为卖方智能体，在 A2A 场景下可以与买方智能体建立信用关系：
- 记录与各买方智能体的历史交易
- 评估买方智能体的履约率和支付及时性
- 对优质买方智能体提供更优惠的条件或更宽松的支付条款

## 技术要求

- 实现 A2A 协议的智能体发现与能力声明接口
- 实现 A2A 任务接口，支持标准任务请求响应
- 实现 `CID-PCA-NEG` 支付能力协商接口
- 实现 HTTP 402 语义扩展的支付诉求响应
- 实现支付凭证的解析和向 PSP 的验证
- 实现履约回执的生成与存证事件上报
- 与 TSD 信任服务域对接支持存证

## 安全考量

- **支付凭证验证**：必须通过 PSP 验证，不能仅依赖买方智能体声明
- **诉求签名**：支付诉求必须经卖方智能体签名，防止篡改
- **时效控制**：支付诉求设置合理有效期，防止重放攻击
- **资源保护**：支付验证完成前不实际出票/消耗库存
- **存证留痕**：全流程存证，支持争议举证

## 参考实现

- **航司空服智能体**：
  - 接收买方智能体的航班查询和预订请求
  - 返回 HTTP 402 支付诉求
  - 接收支付凭证，验证后出票
  - 返回电子客票给买方智能体

- **酒店预订智能体**：
  - 查询房态，返回可选房型
  - 支付诉求包含房型、入住日期、总价
  - 验证支付后向酒店 PMS 创建预订
  - 返回预订确认号

- **用车服务智能体**：
  - 接收接送机需求
  - 基于距离和时间计算价格
  - 支付验证后派单给司机/车队
  - 返回派单信息和司机联系方式
