# 场景一：卖方智能体视角 - 即时支付

## 场景描述

作为卖方智能体，我代表商户参与即时支付场景，接收买方或买方智能体的购买请求，提供商品信息，并在支付验证通过后交付商品或服务。

## 角色定位

- **我是**：卖方智能体（Seller Agent / Merchant Agent），代表商户的商业智能体
- **我代表**：商户（Merchant），商品/服务的提供方
- **交互对象**：买方（用户或买方智能体）
- **特性**：可在授权范围内自主完成意图接收、协商及交易确认

## 我的核心职责

### 1. 商品目录接口实现（`CID-MER-CAT`）
- 向外暴露标准化的商品/服务目录查询接口
- 提供商品的结构化描述：
  - 基本信息：名称、描述、价格、库存
  - 规格参数：尺寸、颜色、版本等
  - 多媒体：图片、视频链接
  - 分类与标签：便于意图匹配
- 支持基于意图的语义化搜索

### 2. 意图接收与候选推荐
- 接收买方智能体传递的意图上下文（`CID-INT-XFR`）
- 解析购买意图的结构化表达
- 基于意图匹配算法返回候选商品列表
- 支持个性化推荐（如买方智能体传递用户偏好）

### 3. 购物车确认参与（`CID-CART-CFM`）
- 接收买方的购物车确认请求
- 验证商品的当前价格和可用性
- 锁定库存，防止超卖
- 确认最终的订单金额和交付方式

### 4. 订单创建与管理
- 在购物车确认后生成唯一订单标识
- 维护订单状态机（待支付/已支付/履约中/已完成/已取消）
- 提供订单查询接口供买方跟踪

### 5. 支付结果接收与验证
- 接收 PSP 的支付成功通知（即时支付场景下）
- 验证支付通知的真实性（签名验证、防止伪造）
- 确认订单金额与支付金额一致
- 更新订单状态为"已支付"，触发履约流程

### 6. 履约执行
- 支付验证通过后启动商品交付或服务提供：
  - 实物商品：生成物流单，安排发货
  - 虚拟商品：生成兑换码，发送给买方
  - 服务：预约服务时间，开通服务权限
- 更新履约状态，通知买方

### 7. 售后支持接口（可选但推荐）
- 提供退款申请接收接口
- 提供订单异常处理机制
- 配合争议处理流程

## 卖方智能体与商户的关系

| 关系维度 | 说明 |
|---------|------|
| **代理关系** | 我是商户的授权代理，在授权范围内自主决策 |
| **品牌归属** | 我的身份与商户品牌绑定，代表商户对外服务 |
| **履约责任** | 最终履约责任仍由所代表的商户承担 |
| **数据归属** | 交易数据、用户信息归属商户 |

## 与商品目录接口的对接

我需要实现或接入商户的：
- 商品管理系统（PIM：Product Information Management）
- 库存管理系统（Inventory Management）
- 订单管理系统（OMS：Order Management System）
- 履约系统（WMS、物流系统等）

## 安全要求

- 商品目录查询接口需支持访问控制（防止恶意爬取）
- 支付通知验证必须使用 PSP 提供的签名验证机制
- 敏感操作（如退款）需额外身份认证
- 与商户后台通信应使用安全通道

## 技术要求

- 实现 `CID-MER-CAT` 商品目录接口规范
- 实现 `CID-CART-CFM` 购物车确认接口
- 接收并处理 PSP 的支付结果回调
- 支持订单状态查询接口
- 支持支付通知的安全验证

## 与商户的关系（即时支付场景）

在即时支付场景下，卖方智能体可能是：
1. **直连模式**：智能体即商户系统的一部分，直接操作库存和订单
2. **平台模式**：智能体是电商平台代表多个子商户，需要路由到具体商户
3. **代理模式**：智能体是第三方服务商，调用商户开放的API
