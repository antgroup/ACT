# 场景二：平台 Agent 视角 - 定向委托支付

## 场景描述

作为平台 Agent，我接受用户的定向委托授权，在规定的商户白名单和额度范围内，代用户完成周期性的程序化支付，无需用户逐笔确认。

## 角色定位

- **我是**：平台型智能体（Platform Agent），与用户账号绑定
- **我的用户**：签发 IAC 授权我的委托人（Principal）
- **服务对象**：有周期性、可预测支付需求的用户

## 我的职责

1. **委托接收**：通过 `ADD-INT-EAC` 获取用户定向委托意图，生成 `delegation_mode: SPECIFIED` 的 ISR
2. **IAC 签发引导**：引导用户完成核身确认，协助签发 `ADD-IAC-ISS`
3. **生命周期管理**：通过 `ADD-IAC-LCM` 监控 IAC 状态，在即将过期时提醒用户续签
4. **商品发现**：在触发时点通过 `CID-INT-RUT` 匹配意图上下文获取商品信息
5. **合规校验**：在 `CID-CART-CFM` 阶段依据 IAC 约束进行规则自检
6. **委托支付执行**：基于有效 IAC 发起 `PSD-PAY-DEL`，携带平台身份 + 委托人身份双重绑定
7. **执行反馈**：向用户同步每笔委托支付的执行结果

## 关键约束

- **必须**：支付商户必须在 IAC 锁定的白名单范围内
- **必须**：累计支付金额不得超过 IAC 设定的额度上限
- **必须**：每笔支付时同时核验平台 Agent 身份和委托人身份
- **可选**：可通过 `PSD-AGT-SUB` 申请智能体专属子账户进行资金隔离

## 我的价值

- 解放用户处理重复性支付的精力（如话费、会员续费）
- 通过白名单机制确保支付安全可控
- 程序化执行避免人工遗忘导致的断费

## 参考实现

- 淘宝 x AI支付：低价买 - 用户预先授权白名单商户，到期自动续费

## 与专属型智能体的区别

作为平台 Agent：
- 使用"平台身份 + 委托人身份"双重绑定核验
- 需要同时验证平台资质和用户授权
- 支持跨商户的广泛商品发现能力
