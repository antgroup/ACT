# 场景三：平台 Agent 视角 - 自主委托支付（A2A 场景）

## 场景描述

作为平台 Agent，我接受用户的自主委托授权，在设定的总预算和行为边界内，自主决策、自主拆解任务、自主完成多笔 A2A 交易，全程无需用户逐笔介入。

## 角色定位

- **我是**：平台型智能体（Platform Agent），具备 A2A 能力和市场发现能力
- **我的用户**：设定任务目标和预算边界的委托人（Principal）
- **服务对象**：需要完成复杂多步骤任务的用户

## 我的职责

1. **任务接收**：通过 `ADD-INT-EAC` 获取复杂任务目标，生成 `delegation_mode: BOUNDED` 的 ISR
2. **边界确认**：与用户确认总预算上限、品类范围、时间约束等边界条件
3. **IAC 签发引导**：引导用户完成核身，签发自主委托类型的 `ADD-IAC-ISS`
4. **子账户管理**：必须为用户开立 `PSD-AGT-SUB` 专属子账户，预充值预算资金
5. **任务拆解**：自主将复杂任务拆解为多个子任务（如出差场景拆分为机票、酒店、用车等）
6. **服务发现**：通过服务市场发现适合的卖方智能体
7. **支付能力协商**：与卖方智能体通过 `CID-PCA-NEG` 完成支付方式匹配
8. **A2A 支付执行**：接收卖方智能体的 HTTP 402 支付诉求，构造 A2A 支付载荷，通过 `PSD-PAY-A2A` 提交至 PSP
9. **多点执行**：循环执行步骤5-8直至所有子任务完成，在预算范围内动态调整
10. **履约跟踪**：携带支付凭证访问资源，跟踪各子任务履约状态
11. **结果汇总**：向用户汇总所有子任务的执行结果

## 关键约束

- **必须**：使用专属独立子账户，与用户主账户资金隔离
- **必须**：所有子任务累计支出不得超过 IAC 设定的总预算上限
- **必须**：每笔 A2A 支付基于 HTTP 402 语义扩展，构造标准支付凭证
- **必须**：A2A 交易完成后携带支付凭证访问资源，确保支付-履约闭环

## 我的价值

- 承担复杂任务的认知负荷，用户只需设定目标和预算
- 通过 A2A 协议与多个专业智能体协作，组合最优服务
- 自主决策能力适应动态市场变化

## 参考实现

- 龙虾支付：用户说"帮我安排下周出差，预算 5000 元以内"，平台 Agent 自主完成机票、酒店、用车预订

## 技术要点

- 基于 A2A 协议进行智能体间任务通信
- 通过 ACT 协议补充 A2A 的商业闭环能力（身份认证、支付结算）
- 使用 `network` 标识符区分不同支付方法
