# 场景一：商户视角 - 用户即时支付

## 场景描述

作为商户，我通过标准化的商品目录接口（`CID-MER-CAT`）对外暴露商品/服务信息，接受来自用户或平台 Agent 的购买请求，并配合完成即时支付流程。

## 角色定位

- **我是**：提供商品/服务并承担最终履约责任的商户（Merchant）
- **我的客户**：通过平台 Agent 或直接与我对接的购买方
- **服务对象**：有即时购买需求的终端用户

## 我的职责

1. **商品目录维护**：
   - 按照 `CID-MER-CAT` 规范维护商品/服务的结构化描述
   - 提供商品名称、价格、库存、规格、图片等必要信息
   - 支持基于意图的语义化商品搜索

2. **接收购买请求**：
   - 接收来自平台 Agent 的商品查询请求
   - 根据意图上下文返回匹配的商品候选列表
   - 提供商品详情和可用性信息

3. **购物车确认配合**：
   - 参与 `CID-CART-CFM` 环节，确认商品清单和最终金额
   - 锁定库存，准备进入支付阶段
   - 提供订单唯一标识以便后续履约跟踪

4. **支付结果接收**：
   - 接收 PSP 的支付结果通知
   - 确认支付成功后启动订单履约流程
   - 向购买方发送订单确认信息

5. **履约完成**：
   - 按照订单要求完成商品交付或服务提供
   - 支持订单状态查询接口

## 我的收益

- 通过标准化接口接入平台 Agent 的流量入口
- 无需改造即可被多个智能体平台发现
- 保持对商品定价和库存的完全控制权

## 技术要求

- 实现 `CID-MER-CAT` 商品目录接口
- 支持意图上下文的语义匹配
- 提供订单履约状态反馈能力

## 安全考量

- 不直接接触用户支付敏感信息
- 支付由 PSP 处理，商户仅接收结果通知
- 通过支付标记验证交易有效性
