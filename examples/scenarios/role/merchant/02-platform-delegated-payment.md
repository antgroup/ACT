# 场景二：商户视角 - 定向委托支付

## 场景描述

作为商户，我接受平台 Agent 基于 IAC 发起的委托支付请求，核验 IAC 的有效性（包括白名单匹配和额度管控），完成扣款并提供履约服务。

## 角色定位

- **我是**：被用户列入白名单的授权商户（Merchant）
- **我的客户**：持有有效 IAC 的委托人
- **服务对象**：通过平台 Agent 发起周期性支付的用户

## 我的职责

1. **白名单准入管理**：
   - 维护被用户列入委托白名单的状态
   - 向用户提供授权入口，便于用户将商户加入 IAC 白名单
   - 接收并存储用户的 IAC 白名单授权信息

2. **接收委托支付请求**：
   - 通过平台 Agent 接收基于 `PSD-PAY-DEL` 的委托支付请求
   - 解析请求中携带的 IAC 凭证和委托人身份信息

3. **IAC 核验**：
   - 核验 IAC 的有效性（未过期、未被撤销）
   - 确认本商户在 IAC 锁定的白名单范围内
   - 检查本次支付后的累计金额是否超过 IAC 额度上限

4. **支付执行**：
   - 将 IAC 凭证提交至 PSP 进行最终验证和扣款
   - 接收 PSP 的扣款结果通知
   - 向平台 Agent 返回支付结果

5. **履约服务**：
   - 支付成功后立即启动履约（如会员权益生效、服务开通等）
   - 向用户发送服务开通/续费确认通知

6. **周期执行支持**：
   - 在委托周期触发时配合平台 Agent 完成自动扣费
   - 支持计划任务调度和触发机制

## 我的收益

- 获客留存：被用户列入白名单后获得长期稳定的周期性收入
- 流失降低：自动续费减少用户因遗忘导致的断费流失
- 体验提升：用户无感支付，无需逐笔操作

## 风险控制

- 严格校验 IAC 白名单和额度，拒绝越权支付请求
- 累计额度管控防止超额扣款
- 支持用户随时通过 IAC 生命周期管理撤销授权

## 技术要求

- 支持 IAC 凭证的解析和验证
- 与 PSP 系统对接完成扣款指令处理
- 支付成功后实时履约，确保用户体验

## 合规要求

- 必须在用户首次授权时明确告知委托范围、额度、周期
- 提供便捷的授权撤销渠道
- 支付前可通过留痕机制向用户发送扣款预告
