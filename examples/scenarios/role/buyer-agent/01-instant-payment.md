# 场景一：通用买方智能体视角 - 即时支付

## 场景描述

作为买方智能体，我代表用户发起购买意图，完成商品搜索、购物车确认，并在用户实时在场时协助完成支付。我是购买方在 ACT 协议中的代理执行者。

## 角色定位

- **我是**：通用买方智能体（Buyer Agent），购买行为的代理执行方
- **我的用户**：发出购买意图的委托人（Principal）
- **交互对象**：卖方（商户或卖方智能体）、PSP、TSD
- **角色抽象**：涵盖平台 Agent、专属 Agent 等所有可能的买方代理形态

## 参与方关系（通用模型）

```
┌─────────────────┐       委托        ┌──────────────────┐
│   委托人 (P)    │◄──────────────────│   买方智能体 (B)  │
│    (用户)       │                   │  (本角色视角)    │
└─────────────────┘                   └────────┬─────────┘
        ▲                                      │
        │  实时确认                             │ 查询/购买
        │                                      ▼
        │                             ┌──────────────────┐
        │                             │  卖方 (S)        │
        │                             │  (商户/卖方智能体)│
        │                             └────────┬─────────┘
        │                                      │ 支付
        │                                      ▼
        │                             ┌──────────────────┐
        └─────────────────────────────│  PSP            │
                                      │ (支付服务提供商) │
                                      └──────────────────┘
```

## 我的核心职责

### 1. 意图代理（`ADD` 域）
- 接收用户的自然语言购买意图
- 将意图结构化表达为 ISR（Intent Structured Rule）
- 在需要时引导用户签发 IAC

### 2. 商品发现（`CID` 域）
- 通过 `CID-MER-CAT` 查询卖方商品目录
- 在 A2A 场景下与卖方智能体协商能力

### 3. 购物车确认（`CID-CART-CFM`）
- 与用户确认最终商品清单
- 向卖方锁定交易状态

### 4. 支付发起（`PSD` 域）
- 根据场景选择支付方式：
  - 即时支付：`PSD-PAY-INS`，唤起收银台
  - 委托支付：`PSD-PAY-DEL`，基于 IAC
  - A2A 支付：`PSD-PAY-A2A`，智能体间直接支付

### 5. 结果代理
- 接收支付结果并反馈给用户
- 处理交易成功/失败后的后续流程

## 买方智能体的分类

### 按绑定关系分类

| 类型 | 特征 | 代表 |
|------|------|------|
| 平台型买方智能体 | 与平台账号绑定，跨商户通用 | 淘宝 Agent、千问 Agent |
| 专属型买方智能体 | 与用户一对一强绑定 | 支付宝智能助理、设备助手 |

### 按决策能力分类

| 类型 | 特征 | 权限边界 |
|------|------|---------|
| 执行型 | 严格按用户明确指令执行 | 单次交易、实时确认 |
| 定向委托型 | 按预设白名单/周期执行 | 固定商户、额度/时间约束 |
| 自主决策型 | 在预算范围内自主决策 | 宽泛边界、多笔 A2A 交易 |

## 即时支付场景下的通用流程

1. **接收意图**：用户表达"帮我买 X"
2. **意图结构化**：解析 ISR
3. **商品查询**：调用 `CID-MER-CAT`
4. **选项呈现**：向用户展示候选商品
5. **确认选择**：用户选定商品
6. **购物车锁定**：调用 `CID-CART-CFM`
7. **支付发起**：调用 `PSD-PAY-INS`
8. **收银台唤起**：引导用户实时确认
9. **结果反馈**：支付成功/失败通知

## 不同形态买方智能体的在即时支付中的差异

| 职责 | 平台型买方智能体 | 专属型买方智能体 |
|------|-----------------|-----------------|
| 商品发现 | 跨平台搜索能力 | 限于设备/应用内，可能需外调 |
| 支付发起 | 直接调用 PSP | 可能需唤起收银台或委托 |
| 身份核验 | 双身份绑定 | 利用设备绑定简化 |

## 我的价值（通用）

- 降低用户决策负担（搜索、比价、确认）
- 结构化意图提升交易精准度
- 代理执行支持异步/自动化
- 支持 A2A 生态下的多智能体协作

## 技术要求（通用）

- 实现 `ADD-INT-EAC` 接口，解析自然语言意图
- 对接 `CID-MER-CAT` 等商业交互接口
- 根据场景调用正确的支付流程接口
- 支持存证事件上报（与 TSD 对接）

## 与平台 Agent/专属 Agent 文档的关系

本文档提供买方智能体的**通用抽象视角**，定义所有买方智能体的共通职责和流程：

- `platform-agent/*.md` ← 平台型买方智能体的具体实现细节
- `agent/*.md` ← 专属型买方智能体的具体实现细节

具体实施时，买方智能体应结合自身形态，参考对应角色的详细文档。
