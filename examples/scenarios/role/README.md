## 角色分类与说明

### 核心交易参与方

| 角色 | 定位 | 核心职责 | 代表实体 |
|------|------|---------|---------|
| **platform-agent** | 平台型智能体 | 跨平台商品发现、IAC 委托执行、A2A 任务代理 | 淘宝 AI、千问 AI |
| **agent** | 专属型智能体 | 与用户一对一强绑定、专属子账户隔离、深度个性化 | 支付宝智能助理、设备助手 |
| **merchant** | 商户 | 提供商品/服务，承担履约责任 | 电商平台、航司、酒店集团 |

### 抽象角色视角

| 角色 | 定位 | 说明 |
|------|------|-----|
| **buyer-agent** | 通用买方智能体抽象 | 涵盖 platform-agent 和专属 agent 的共通职责和流程，提供买方视角的通用模型 |
| **seller-agent** | 卖方智能体 | 代表商户参与 A2A 交互，是商户在 A2A 场景的智能代理 |

### 基础设施服务方

| 角色 | 定位 | 核心职责 |
|------|------|---------|
| **psp** | 支付服务提供商 | 支付受理、IAC 验证、扣款执行、子账户管理、资金清算 |
| **tsd-provider** | 信任服务提供商 | 智能体身份管理、存证服务、链上锚定、争议处理、声誉评估 |

| 场景 | 平台 Agent | 专属 Agent | 商户 | 卖方智能体 | PSP | TSD |

| 二、定向委托 | IAC 执行、双重身份 | IAC 执行、专属身份、子账户 | 白名单核验、周期履约 | IAC 接入、委托履约 | IAC 核验、额度管控 | IAC 存证、执行审计 |
| 三、自主 A2A | 任务拆解、A2A 协调 | 任务拆解、A2A 个性化执行 | HTTP 402、凭证验证 | 支付诉求、凭证验证 | 子账户、多笔扣款 | A2A 存证链、声誉评估 |

## 与通用场景的关系

本目录的视角描述与 `../common/` 目录的通用场景描述形成对应关系：

| 通用场景 | 对应角色视角文件 |
|---------|-----------------|
| `../common/01-instant-payment.md` | `platform-agent/01-*.md` + `merchant/01-*.md` + `psp/01-*.md` + `tsd-provider/01-*.md` |
| `../common/02-platform-delegated-payment.md` | `platform-agent/02-*.md` + `merchant/02-*.md` + `agent/02-*.md(对比)` |
| `../common/03-dedicated-delegated-payment.md` | `agent/02-*.md` 为主，`platform-agent/02-*.md` 作为对比参考 |
| `../common/04-autonomous-delegation.md` | `platform-agent/03-*.md` + `merchant/03-*.md` + `agent/03-*.md` + `seller-agent/*.md` |

**使用建议**：
- **通用场景**：提供完整的技术流程和协议组件说明，适合理解整体机制
- **角色视角**：帮助特定参与方理解"我需要做什么"、"我需要对接谁"、"我的约束是什么"

## 角色视角文档的特点

每个角色视角文档都包含以下要素：

1. **角色定位**：定义"我是谁"、"我与谁交互"
2. **核心职责**：列出该角色在该场景下的具体职责清单
3. **协议映射**：将职责映射到具体的 ACT 协议组件
4. **关键约束**：MUST/SHALL/SHOULD 级别的关键要求
5. **与他人的关系**：与其他参与方的协作关系说明
6. **技术要求**：需要实现的接口、对接的服务
7. **参考实现**：真实场景中该角色的具体形态示例
